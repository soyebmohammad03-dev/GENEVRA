# Final Research Status (Independent Audit, 2026-09-13)

This document is the output of an independent, adversarial audit of GENEVRA at commit 29d533f, performed by a session with no prior involvement in building the codebase. It verifies or corrects the prior implementation team's own self-graded quality-gate documents (`docs/phase_15_16_quality_gate.md`, `docs/phase_17_18_quality_gate.md`, `docs/final_research_quality_gate.md`) rather than accepting them. See `docs/final_evidence_matrix.md` and `docs/final_claim_matrix.md` for the underlying per-question detail.

## What was independently re-verified and found accurate

- **Engineering claims.** 714/714 tests pass, `ruff check` clean, `ruff format --check` clean, `mypy` (project config) clean — all independently rerun, not taken on faith.
- **Reproducibility.** `python -m genevra.cli verify-evidence` returns `ok:true` on the committed package. Deliberately corrupting `research_evidence/statistics/rq2_sensitivity.json` was detected (`checksum mismatch`); restoring it returned to clean. Rerunning `experiments/baseline.py --seed 0` twice produced byte-identical output; `--seed 1` produced different output, as expected.
- **Negative-results disclosure is real, not decorative.** `research_evidence/reports/negative_and_inconclusive_results.md` lists 6 of the 8 RQs by their actual non-supporting status (INCONCLUSIVE x3, NOT_SUPPORTED, INSUFFICIENT_DATA x2) with real, specific caveats — this is not a placeholder document.
- **No metabolic cost for plasticity/learning.** Confirmed by reading `src/genevra/organism/metabolism.py` in full: `MetabolicParams` and `Metabolism.cost_for`/`apply_step` only reference move/stay/eat/base-upkeep energy costs. No reference to `plasticity_gate` or `learning_rate` exists anywhere in the file. The prior team's own disclosure of this gap is accurate.
- **Data-to-figure traceability.** RQ2's `robustness_vs_evolvability.png`/`.json` pair was manually cross-checked against `research_evidence/statistics/rq2_robustness_evolvability.json`: all 10 (robustness, evolvability) pairs (e.g. seed 7: robustness=9.327, evolvability=2.952) are visibly present as the correct scatter points in the rendered PNG, and the reported Pearson r=0.0955 matches a visibly near-zero-correlation cloud. No fabrication found in this chain.
- **RQ statuses other than RQ4 are honestly labeled.** RQ1/RQ2/RQ6 = INCONCLUSIVE, RQ3 = NOT_SUPPORTED, RQ5/RQ8 = INSUFFICIENT_DATA, RQ7 = PARTIALLY_SUPPORTED all match what their own statistics files support; none of these were overclaimed.

## What was found wrong and corrected by this audit

- **RQ4 was mislabeled `SUPPORTED`.** `experiments/exp1_isolated_vs_shared.py` compares two entirely different simulation engines (`EvolutionEngine`+`GridWorld`, discrete generations, tournament selection, `channels=2` vs. `ContinuousEvolutionEngine`+`SharedGridWorld`, continuous overlapping generations, birth/death reproduction, `channels=3`). The experiment's own docstring says plainly: *"This is an infrastructure-validation experiment... One run at one configuration establishes nothing about whether ecological interaction generally increases or decreases diversity."* Despite this, the machine-readable `evidence_status` field said `SUPPORTED`, and the README/quality-gate prose described it as GENEVRA's one result with "a real, large, statistically significant effect," without foregrounding the confound at the status-label level (it was disclosed only in a limitations sentence and in one Q&A item of the quality-gate doc). This is graded generously: the team disclosed the confound in prose but did not let it change the formal status. **Corrected**: `evidence_status` changed to `CONFOUNDED` in `research_evidence/research_questions/RQ4.json`, `research_evidence/reports/RQ4.md`, and `research_evidence/tables/research_question_matrix.{csv,md}`; `docs/final_research_quality_gate.md` and `README.md` amended with an audit-correction note. The underlying data (`rq4_ecology.json`, the p-value, Cohen's d) is untouched — only the status label and its stated meaning changed. The checksum manifest was regenerated using the project's own `genevra.evidence.checksums.write_checksum_manifest` (no new code) to reflect this legitimate content change; `verify-evidence` is clean again.
- **No family-wise multiple-comparisons correction across the 8 RQs.** `src/genevra/discovery/multiple_testing.py` implements Benjamini-Hochberg FDR correction, but no file under `research_evidence/statistics/` contains an FDR-adjusted p-value. All p-values reported (RQ1/RQ4/RQ6's permutation tests) are raw. With RQ4 as the sole nominally significant result among 8 simultaneous tests, and now known to be confounded besides, the "one strong result" framing in the README/quality-gate docs materially overstated what survives correction plus the architectural review. This is disclosed here rather than silently fixed, since applying real FDR correction to already-computed p-values without rerunning anything would just relabel one already-confounded number — not worth doing as a "fix."

## Update (targeted correction, 2026-09-13): RQ4b, the same-engine ecology experiment

The corrected same-engine ecology comparison this audit's status update called for has now been run for real: `experiments/exp_ecology_corrected.py`, both conditions on `ContinuousEvolutionEngine`+`SharedGridWorld`, identical architecture/organism config/mutation/reproduction settings, varying only `resource_a_density` (0.30 `minimal_competition` vs. 0.05 `shared_competition`). A pre-analysis plan (`research_evidence/configurations/rq4_corrected_analysis_plan.json`) was frozen to disk *before* the experiment ran, declaring `genotypic_diversity` as the sole primary outcome and `min_sample_size=20`; the result is therefore CONFIRMATORY, not exploratory.

24 independent seeds per condition were run (exceeding the pre-registered 20-seed minimum; the full 48 simulation runs took ~24 seconds wall-clock, so the "not cheap within budget" estimate below this section — written before this run — undersold how fast this design actually is once decoupled from the original 8-seed/10-generation script's assumptions). Result: **NOT_SUPPORTED**. Permutation p=0.7313, Cohen's d=-0.10 (negligible), bootstrap 95% CIs for the two condition means overlap heavily ([7.04, 8.66] vs. [6.71, 8.52]), and per-seed replication consistency shows an agreement_fraction of exactly 0.5 with 12 of 24 sign reversals — seeds are genuinely split on direction, not a real effect obscured by noise. See `research_evidence/research_questions/RQ4b.json`, `research_evidence/reports/RQ4b.md`, `research_evidence/tables/rq4_historical_vs_corrected.md` (which preserves the original CONFOUNDED result side-by-side rather than erasing it).

An FDR correction family was also built (`research_evidence/statistics/rq_family_fdr.json`) over the two genuinely confirmatory permutation tests in the package (RQ1/RQ6's case_a_reproduction result and RQ4b) — the original CONFOUNDED RQ4 was deliberately excluded from this family since it is not a valid test of its stated question. Both p-values (0.8171 and 0.7313) remain far from significant after BH correction (adjusted p = 0.8171 for both); this changes no conclusions, since neither survived even before correction.

**This does not change what GENEVRA can claim about ecology in the affirmative** — it only removes the ambiguity: there is now a well-powered (n=24), methodologically clean, single-variable test of resource-scarcity competition intensity on genotypic diversity, and it found no effect. That is itself informative (a genuine negative result, not an absence of evidence) but must not be read as "ecology doesn't matter" — only one parameter and one metric were tested. The sections below (written before this correction) are retained as-is except where a strikethrough-style note updates them for what actually changed.

## What GENEVRA can currently claim

- A working, reproducible, checksum-verified, deterministic evolutionary-simulation and evidence-generation pipeline (engines, metrics, statistics, campaign/provenance machinery, figure/table generation) that runs end-to-end on real data, at laptop scale.
- Honest reporting infrastructure: negative and inconclusive results are preserved and labeled as such rather than hidden, for 7 of the original 8 RQs, now 8 of 9 including RQ4b.
- One reproducible, seed-level (n=8), non-pseudoreplicated statistical difference between two specific simulation pipelines' final genotypic diversity (RQ4's raw numbers), without a validated causal or even clean-associative link to "ecological interaction structure" as a single variable — this remains CONFOUNDED and unchanged.
- A well-powered (n=24), single-engine, single-variable test of resource-competition intensity on genotypic diversity (RQ4b), which found **no significant effect** (NOT_SUPPORTED) — this is now GENEVRA's cleanest completed ecology experiment, precisely because it found nothing, not despite it.

## What GENEVRA cannot currently claim

- Any validated finding about evolvability, novelty, robustness, learning-strategy convergence, or discovery-driven hypothesis generation — all remain INCONCLUSIVE/NOT_SUPPORTED/INSUFFICIENT_DATA/EXPLORATORY at current sample sizes (n=3-10).
- That ecological interaction structure (specifically, in the original RQ4 sense) affects evolutionary dynamics — the only evidence for the original claim (RQ4) remains confounded, and the corrected same-engine test (RQ4b) found no effect of the one parameter it manipulated.
- That ecological interaction structure *never* affects evolutionary dynamics in GENEVRA — RQ4b tested one parameter (`resource_a_density`) and one metric (`genotypic_diversity`); a null there does not generalize to other ecological parameters (`max_agents`, spatial structure) or other outcome metrics.
- Any claim about biological plasticity trade-offs being modeled with a real cost — plasticity/learning rate carry zero metabolic cost in the current model.
- Family-wise statistical rigor across the full evidence package beyond the two-test confirmatory family now built — RQ2/RQ3/RQ5/RQ7/RQ8's analyses remain outside any correction family, correctly, since they are exploratory/descriptive rather than confirmatory hypothesis tests (see `research_evidence/statistics/rq_family_fdr.json`'s stated rationale).

## What has/hasn't replicated

- RQ3 is the only original RQ that used genuine held-out (leave-one-seed-out) validation, and the predictive relationship it tested did **not** replicate (NOT_SUPPORTED).
- RQ4b is the second RQ in this package with genuine per-seed replication analysis (not just a pooled test): `agreement_fraction=0.5` is itself the finding — the near-zero pooled effect is not replication-consistent in the trivial sense of "always near zero," it is inconsistent in direction across seeds, which is a stronger and more informative null than a low-powered non-significant pooled test alone would be.
- No RQ (other than RQ4b, now) was rerun with an independent second seed batch to check external replication.

## What needs more data vs. architectural change

- **More data would likely help**: RQ1/RQ2/RQ5/RQ6/RQ8 — all are underpowered (n=3-10) but methodologically sound designs; more seeds could move these from INCONCLUSIVE/INSUFFICIENT_DATA toward a real answer.
- ~~**Architectural change is required, not more data**: RQ4 cannot be fixed by adding seeds...~~ **Done.** The same-engine correction described here was executed with existing code only (`ContinuousEvolutionEngine`, `SharedGridWorld`, varying `resource_a_density`) — see the update section above. The original RQ4 script itself was not modified; a new script (`experiments/exp_ecology_corrected.py`) was added alongside it, and RQ4's original CONFOUNDED status and data are untouched.
- The natural next ecology experiment is now: repeat RQ4b's design varying a *different* ecological parameter (e.g. `max_agents`, or a spatial-structure regime via `genevra.ecology.spatial`) and/or a different outcome metric (behavioral diversity is now directly comparable across both conditions, since both use the same engine this time — unlike the original RQ4, where the two engines' data models made behavioral diversity incomparable).
- Plasticity-cost modeling (to make the plasticity/evolvability trade-off literature comparisons meaningful) requires an actual metabolic-cost term keyed to `plasticity_gate`/`learning_rate` in `genevra.organism.metabolism` — an architectural addition, not a data question. Still out of scope for this correction pass's no-new-features policy; flagged here as the next real feature, not fixed.

## Scorecard-relevant summary

The codebase's engineering hygiene (tests, types, lint, determinism, checksum provenance) is genuinely strong and was independently confirmed, not just self-reported. The scientific honesty of the underlying team is also genuinely above average for this kind of project — the original 7 of 8 RQs were honestly labeled non-supporting, and disclosure documents exist and are substantive, not placeholders. The one real lapse found (RQ4's status label overstating a confounded infrastructure comparison) has been corrected: the original result is preserved and clearly relabeled CONFOUNDED, and a proper same-engine replacement experiment (RQ4b) was run at n=24 per condition and found no effect, which is reported plainly rather than adjusted to manufacture significance. A confirmatory-family FDR correction now exists for the two hypothesis tests that qualify for one; it does not change any conclusion because neither test was significant to begin with.
