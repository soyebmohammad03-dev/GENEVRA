## Reproduce

Download and verify the checksummed source and capsule archive from [the research release](https://github.com/soyebmohammad03-dev/GENEVRA/releases/tag/phase-29-research). From the extracted source directory run:

```sh
shasum -a 256 -c RELEASE-SHA256SUMS
sh scripts/reproduce_final_research.sh "$PWD/../genevra-run" \
  release-inputs/GENEVRA_PHASE20_REPLAY.zip
```

Alternatively start from a clean checkout and let the runner download the pinned historical capsule:

```sh
git clone --branch phase-29-research https://github.com/soyebmohammad03-dev/GENEVRA.git
cd GENEVRA
sh scripts/reproduce_final_research.sh "$PWD/../genevra-run"
```

The reference platform is macOS arm64 and CPython 3.12.15. Install uv. Allow at least 2 GiB of disk and network access to install the [pinned replay dependencies](../phase_23/requirements-macos-arm64.txt) and [publication dependencies](../phase_28/requirements-publication.txt). The bundled capsule removes the need for a second research-data download. Phase 18 raw records are bundled. Phase 25 records are regenerated by their pinned source and checked against the frozen receipt. No hidden workspace files are needed.

The command verifies checksums, regenerates frozen results, runs the separate reference, reproduces all figures and tables, and reconstructs the final PDF and [audit receipt](rendered/audit-receipt.json). Each stage fails on a digest or numerical mismatch, leaving its outputs in the new directory for diagnosis. Read the first failed stage or failing checksum, preserve the partial log, and see the [challenge discrepancy format](CHALLENGE.md). A failed attempt can be retried with a different new output path. See the release verification receipt for wall time and peak memory measured in a clean internal checkout. Cross-platform byte equivalence has not been demonstrated.
