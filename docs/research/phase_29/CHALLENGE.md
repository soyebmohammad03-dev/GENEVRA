# Public GENEVRA reproduction challenge

Participation is voluntary. Researchers may operate the supplied scripts, write a separate implementation, or critique the target, cost model and inference. Internal clean-clone verification is recorded separately from any external response.

1. Obtain release `phase-29-research` from the public repository or clone its exact tag. Verify the asset SHA-256 manifest and the [frozen manifest](FROZEN_SHA256SUMS).
2. Use macOS arm64, uv, CPython 3.12.15 and the pinned packages listed in the [reproduction guide](README.md). Run the command against the verified bundled archive or its pinned public counterpart.
3. Expect 0/512 shared-blind mean coverage, 180/512 unconditional false certificates, 180/180 among issued and 0 wrong threshold labels. Verify the simultaneous upper unconditional bound .4072946235754177. The primary useful counts must be 1, 104 and 229 out of 256. Recover −103/256 and its paired interval [−.5721064394675774, −.23258106053242256], with all 17 adjusted secondary intervals including zero.
4. Require exact key inventories, counts and costs. Floating score endpoints and width components may differ by at most 1e−9 in separate implementations. The reference environment requires exact generated bytes. Treat other-platform rendering differences separately from numerical differences.
5. Optionally follow the [external evaluation protocol](../phase_27/EXTERNAL_PROTOCOL.md) to independently rebuild the mathematics before inspecting expected outputs. Report the limits of the inference even when calculations agree.

## Submission and discrepancies

Open a voluntary public [repository issue](https://github.com/soyebmohammad03-dev/GENEVRA/issues) titled “Phase 29 reproduction” with the tagged commit, archive digest, environment, exact commands, wall time, peak memory and result. Include the audit receipt and any separate calculator. Disclose prior code access, affiliations and conflicts. Do not post credentials, personal data or local private paths.

For a discrepancy report the exact file, method, case and replicate or table cell, expected and actual values, tolerance and commands. Distinguish integrity failures, rendering-only differences and scientific disagreements. Preserve logs and outputs. Code corrections can be proposed as PRs with a reproducible test, while frozen files should be left in place. A report of failure is useful evidence. No response or endorsement is implied.
