# GENEVRA external evaluation protocol v1

**Status.** Prepared for an independent statistician or research group. No external execution, endorsement or access commitment is recorded.

**Question.** Can a researcher outside the project reconstruct the frozen failure cases and judge whether the combined benchmark adds practical evidence beyond partial-identification, survey and simulation toolkits?

## Materials and reviewer independence

Use a fresh public research-branch clone at an exact commit. Retrieve the verified [capsule catalog](../archive.json), the Phase 18 configs and counts in that capsule, the Phase 19 extension config, Phase 25 receipt and source, and the [mathematical specification](DESIGN_AND_COMPARATORS.md). All benchmark data are synthetic and publicly regenerable. No personal data or private developer environment is required. Cite any offline asset digest. Keep external descriptive Census evidence separate.

Disclose institutional, funding, authorship, contributor, collaboration and other conflicts before evaluation. Distinguish independent artifact operation, independently written numerical reconstruction, and review of scientific relevance. Declare any prior GENEVRA code access or involvement. A reviewer with a conflict can supply useful technical evidence, identified separately from independent judgment.

## Procedure and acceptance criteria

1. Record commit, archive hash, OS, interpreter, dependency versions and full commands. Run the documented [challenge](README.md) without modifying frozen inputs. Record failures, memory and time.
2. Separately reconstruct from the published specification and raw counts. Recalculate the Phase 25 target and likelihood hull, exact spend, endpoints, primary pair counts and interval. Use source anchor counts to score Phase 18 certificates and reconstruct its simultaneous risk bound. For independent numerical adjudication, write a separate calculator before using final expected tables as comparison targets.
3. Compare outputs. Require exact keys, budgets, counts and decisions, and absolute difference ≤1e−9 for score endpoints and reported interval endpoints. In Phase 25 expect 0 proxy-only and 103 variance-only useful pairs. Check the primary interval separately from the 17 adjusted contrasts. In Phase 18 verify 180 false certificates, 0 coverage and 0 false threshold calls in shared blindness, plus the corrected risk upper bound. Figure bytes should match on the reference platform. Report cross-platform numeric equivalence and rendering differences separately.
4. Assess the access and cost ledger. Identify assumption violations or advantaged methods. Compare the closest external artifact on estimand, costs and evidence. Give an explicit judgment of usefulness and claim limits. Numerical agreement alone does not pass scientific novelty or external validity.

Return a dated report with commands, hashes, test logs, independent code and findings. For discrepancies include file or case/key, expected and observed value, tolerance, environment, suspected cause and reproduction steps. Preserve originals and every failure. Distinguish a resolved rendering discrepancy, a material numeric discrepancy, and an unresolved scientific assumption. Submit via a repository issue or other mutually agreed channel. The project does not promise review or approval.

A later withheld evaluation requires a separate custodian and locked policies before unblinding. Empirical validation requires an independently enumerated target frame, governed outcomes, cost records and approvals. Neither is an acceptance condition for a technical replay, and neither can be inferred from one.
