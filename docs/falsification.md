# Falsification (Phase 11.5-11.7)

GENEVRA's discovery and literature-reproduction machinery is easy to
misuse in one specific way: run enough comparisons, and something will
look "significant" by chance, then read the significant result as proof
of the mechanism you expected. This document describes the pieces built
specifically to resist that failure mode.

## Alternative explanations, not just one hypothesis

`genevra.literature.alternative_explanations.AlternativeExplanation` is a
structured competing explanation for an observed association:

```python
@dataclass(frozen=True)
class AlternativeExplanation:
    explanation_id: str
    description: str
    predicted_signature: str  # what would distinguish it
    discriminating_experiment: str  # how to test it
    required_control: str
    status: Literal["untested", "ruled_out", "supported", "inconclusive"]
    evidence: tuple[str, ...]
    provenance: tuple[str, ...]  # ResearchMemory record ids
```

`standard_alternative_explanations(independent_variable,
dependent_variable)` generates one entry per confound in
`STANDARD_CONFOUNDS`: mutation rate, population size, environmental
volatility, environmental predictability, cue reliability, lineage
history, survival bias, baseline fitness, metric definition, stochastic
variation. Every entry starts `status="untested"` — nothing in this
codebase ever marks one `"ruled_out"` automatically. Only running the
named `discriminating_experiment` and recording its outcome should move
`status`, and that update is left to the researcher (or a future
automated loop built on `genevra.discovery.loop`), not performed
implicitly here.

## Generating hypotheses designed to disprove, not just confirm

`genevra.literature.falsification.generate_falsification_hypotheses`
takes one observed association and returns:

- **H1**: the claimed mechanism itself.
- **H2..H11**: one hypothesis per standard confound — "X may drive the
  association instead of the claimed mechanism."

Each is a `genevra.discovery.hypothesis.Hypothesis`, so it flows through
the exact same evaluation path (`genevra.discovery.loop.evaluate_hypothesis`,
`genevra.discovery.replication.ReplicationRunner`) as a hypothesis
generated by the discovery engine — there is deliberately no separate
"falsification-only" evaluation rule that could quietly apply a lower
evidence bar.

`generate_falsification_experiments` turns each hypothesis into a
`genevra.discovery.followup.ProposedExperiment` via the existing
`generate_followup_experiment` — again, no parallel experiment-design
logic.

## Causal language safeguards

Every report generated by `genevra.literature.report` and
`genevra.innovation.report`:

- States effect direction/magnitude/significance as separate, explicit
  fields (`observed_direction`, `cohens_d`, `p_value`) rather than a
  single verdict.
- Never uses "X causes Y" language. The strongest phrasing used anywhere
  in a generated report is "under the tested GENEVRA conditions, X was
  associated with Y" or "the pre-registered primary metric moved in the
  predicted direction."
- Explicitly labels genealogical-descent edges in
  `genevra.innovation.dependency_graph.InnovationDependencyGraph` as
  "evidence of opportunity, not proof of causal dependency."
- Keeps `genevra.analysis.counterfactual.CounterfactualResult`'s
  mechanism/outcome distinction: a controlled single-genotype
  perturbation's measured consequence is never described as "the
  mechanism causes the outcome across the population."

A quick reference for what is/is not said anywhere in a generated report:

| Never said | Sometimes said (with evidence) |
|---|---|
| "Plasticity causes innovation." | "Under the tested GENEVRA conditions, higher plasticity was associated with increased future novelty." |
| "GENEVRA proved X is open-ended." | "No evidence of saturation was observed within the tested horizon." |
| "This reproduces paper Y." | "GENEVRA reproduced the qualitative pattern described in paper Y, under GENEVRA's own model assumptions." |
| "The correlation confirms the hypothesis." | "The replication's bootstrap CI excludes zero and agrees in sign with the predicted direction (label: supported)." |

## Multiple-testing awareness

Any falsification sweep that tests several confounds' discriminating
experiments at once is "many relationships examined," exactly the
scenario `genevra.discovery.multiple_testing.benjamini_hochberg` exists
for. A researcher running several `AlternativeExplanation` discriminating
experiments together should feed the resulting p-values through
`benjamini_hochberg` before treating any single one as noteworthy — this
module does not do that automatically, since it does not itself run
experiments, but the requirement is the same one already documented in
`genevra.discovery.correlation`.
