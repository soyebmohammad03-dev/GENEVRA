# Submission source encoding inventory

The [machine-readable inventory](source-encoding.json) distinguishes three sets. The manuscript attachments comprise the exact LaTeX and BibTeX used for the compiled paper. Both are ASCII and LF. The current runtime software candidate contains 159 Python files, of which 147 have UTF-8 content beyond ASCII. The inventory records each path, encoding status and the affected Python token categories. Three files in the wheel are byte-identical copies of the original runtime experiment scripts.

The third set is a review pool of 27 tracked checkout scripts, including the verification entry point. Ten contain non-ASCII text. The planned replication attachment uses the publication, reference and replay drivers from that pool plus the three frozen layers of research inputs. The separately acquired archive contains historical source snapshots and is outside the submission software tree. Unit tests, development-only tooling, the Phase 31 diagnostic, and unrelated historical modules serve repository verification and need no separate manuscript attachment. The complete installed GENEVRA source remains the software candidate, so the wheel's ASCII issue applies to any upload of that source.

UTF-8 is appropriate for the installed package. The JSS upload explicitly requires ASCII code. Mechanical substitutions in executable strings, raw strings, notation or frozen sources can change output and hashes. An ASCII-specific upload remains open pending review of the exact software and replication source selection and verification of any representation changes.
