## Multiple-comparisons note

`src/genevra/discovery/multiple_testing.py` implements Benjamini-Hochberg FDR correction and is used internally by the discovery engine, but grepping every file in `research_evidence/statistics/` for `fdr`/`q_value`/`adjusted` returns **no hits**. The 8 RQs' p-values (where computed at all: RQ4 and, implicitly, RQ1/RQ6's permutation tests) are reported raw, with no family-wise correction across the 8-question family. RQ4 is the only nominally "significant" result among 8 simultaneous tests; at an uncorrected alpha of 0.05 this is exactly the kind of single hit a strict skeptic would expect from multiple testing even before considering the RQ4 confound described below. This is a real gap, not an invented one — the correction machinery exists in the codebase but was not applied at the evidence-package level.

## RQ4 audit finding (see `docs/final_research_status.md` for full detail)

`experiments/exp1_isolated_vs_shared.py`'s own docstring states: *"This is an infrastructure-validation experiment... One run at one configuration establishes nothing about whether ecological interaction generally increases or decreases diversity."* The isolated condition uses `EvolutionEngine` + `GridWorld` (discrete non-overlapping generations, tournament selection, `channels=2`, i.e. a 2-plane sensory input and a smaller network `input_size`), while the shared condition uses `ContinuousEvolutionEngine` + `SharedGridWorld` (continuous overlapping generations, birth/death reproduction, `channels=3`). These are two different engines with different selection dynamics, different generation structure, and literally different-sized neural network inputs — not a single-variable ecological manipulation. The audit reclassified this from `SUPPORTED` to `CONFOUNDED`; the underlying statistic (p=0.0005, d=2.77) is real and reproducible but cannot be attributed to ecological sharing specifically.
